## Exact contract

A request remains `state=requested` permanently (historical intent); execution creates a **different** `ir_workspace_scaffolds` record. POST body is exactly `{operation_id: UUID}`; the URL client must literally match the request client, generated tenant ID and policy tenant. GET has no body. Unknown routes/methods and malformed literal identifiers fail closed. API responses are `{scaffold: record|null}`. POST returns 200 only after a separate authorized RPC read matches the written immutable record. GET does not create anything.

RPC `execute_ir_provisioning(p_client_id text, p_operation_id uuid)` checks `require_active_profile()` and current `is_master_admin()` (active, unrevoked appointment; active profile; persisted MFA flag; AAL2), locks the client, checks eligible lifecycle, then binds the exact existing request. RPC `get_ir_workspace_scaffold(p_client_id text)` repeats authorization and returns persisted scaffold including canonical policy bytes. Recovery reads remain available to authorized platform administrators for suspended/archived clients; execution/retry is blocked there.

The scaffold record contains client_id, generated tenant_id, operation_id, idempotency_key (from the request), policy_json (text), state=`scaffold_persisted`, runtime_ready=false, created_by and created_at. SQL generates a fixed **built-in empty-scaffold policy**, not a Hacker Dojo clone or an operational policy approval. `format=ir-policy-v1`, version=`fi-empty-v1`, display_name=literal client ID, source_path=null. It uses the exact `TenantPolicy.to_dict()` fields from IR `policy.py:71-115` and strict canonical serializer `storage/workspace.py:53-100`: ASCII, lexicographically sorted object keys, no whitespace. Confidence is 0.75/0.95, evidence kinds invoice/receipt/accounting_ref, donor-visible evidence required, attribution default DIRECT_RESTRICTED with **empty allowed methods**, all nine existing L3 command names retained, separate send approval required, **empty email topics**, fixture consent false. No fabricated file provenance. A future policy revision needs a separately reviewed migration/contract, not an overwrite parameter.

“Empty scaffold” means an immutable policy binding and reservation in the dedicated FI Supabase scaffold namespace. It does **not** initialize or adopt IR Python tables, ledger, finance, outbox, object storage or an existing legacy IR tenant. No claim is made that legacy IR databases are empty or reserved; they must never adopt these records without a separately authorized migration and tenant-state exclusion protocol. Runtime binding, policy approval, organization documents, operational readiness and activation remain unimplemented and false. There is no runtime read/write endpoint in this slice.

## Atomicity and recovery

SQL transaction commits scaffold and audit together. Client row lock serializes concurrent calls; same operation returns the same stored bytes, different operation fails without overwriting. Unique client/operation/idempotency bindings and generated tenant ID enforce identity. Direct table privileges are revoked including service_role; RLS has no policies. An immutable trigger rejects UPDATE/DELETE even accidental owner DML (DB owners can of course alter DDL). Request payload/state semantics remain unchanged; a composite unique key supports the scaffold foreign key binding (client, operation, idempotency key). Network failure after commit is an uncertain response: GET or retry the same operation recovers. No queue, lease, background host or additional database is necessary because the entire durable operation is one Supabase transaction.

## Security boundary / configuration

Worker requires Bearer auth and configured `PLATFORM_SUPABASE_URL` plus `PLATFORM_SUPABASE_ANON_KEY` (or existing SUPABASE aliases). Supabase Auth `/auth/v1/user` validates the token, then user-authenticated PostgREST RPC rechecks live human authority on every write/read. The Worker does not grant itself authority or trust headers/decoded claims. No service-role fallback, tenant membership fallback, CORS wildcard, public pilot or arbitrary RPC proxy. Responses are no-store; upstream errors are sanitized. Browser uses the existing Supabase session and same-origin fetch; no persistent bearer storage is added.
